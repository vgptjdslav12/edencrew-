# 이든크루 Flutter 과제

관심 / 검색 / 상세 세 화면을 Flutter 로 구현한 저장소입니다. 과제 요구사항은 [`docs/ASSIGNMENT.md`](docs/ASSIGNMENT.md) 를 참고해 주세요.

## 실행

```bash
flutter pub get
flutter test  # 옵션
flutter run
```

- Flutter 3.38.5 / Dart 3.10.4 로 개발했습니다.
- 확인 환경은 Android 에뮬레이터 (Pixel 5, API 34) 위주입니다. Windows / macOS 데스크톱에서도 뜨긴 하지만, 창 크기를 Figma 프레임(393×852) 정도로 좁혀 확인하시는 편이 자연스럽습니다.
- 웹(Chrome) 은 Naver endpoint 가 CORS 를 막고 있어 실사용이 어렵습니다. 확인은 에뮬레이터 또는 데스크톱으로 부탁드립니다.
- 폰트는 스타터에 포함되어 있던 Noto Sans KR 을 그대로 사용했습니다.

## 뭘 만들었나

필수 요건 세 화면과 상태 동기화까지 모두 구현했습니다.

- 관심: 목록, 상승 / 하락 / 보합 색, 스켈레톤, 새로고침, 빈 상태, 정렬 3종 바텀시트
- 검색: 입력 + 지우기, 검색어 하이라이트, 관심 토글 + 토스트, 초기 / 결과 없음 상태, 결과 탭 시 상세로 이동
- 상세: 헤더, 큰 현재가, 기간 탭 4개, 캔들 차트, 요약 카드, 일별 시세 표
- `WatchlistStore` 하나가 세 화면의 관심 상태 source of truth 역할을 합니다.

추가로 넣은 것들 (선택 항목):

- Pull to refresh
- 검색 디바운스 200ms + 로딩 인디케이터
- 토스트 fade + slide 애니메이션
- 일별 시세 페이지 캐싱 · 필요한 만큼만 이어받기 (아래 별도 섹션에서 다룹니다)

구현하지 못한 선택 항목:

- 관심 스와이프 삭제, 정렬 기준 재실행 유지, 최근 검색어
- 차트 축 라벨 · 거래량 바 · 크로스헤어 · 영역 채우기 · 전환 애니메이션
- 일별 시세 무한 스크롤

`flutter test` 로컬 결과:

```
00:03 +2: All tests passed!
```

- `test/parsers_test.dart` — 파서 4종 (자동완성 / 실시간 / 메타 / 일별 HTML)
- `test/widget_test.dart` — 앱 초기 진입 시 관심 빈 상태 노출 확인

## 기술 선택

**상태관리는 provider + ChangeNotifier 를 골랐습니다.** 화면 3개 · 스토어 3개 규모에서는 Riverpod / BLoC 가 과하다고 판단했습니다. 관심 상태를 세 화면에서 공유해야 해서 InheritedNotifier 만으로도 가능은 하지만, `context.watch / read` 의 가독성이 좋아 provider 를 얹었습니다.

**폴더는 data / state / ui 3단으로 나눴습니다.**
- `data/` : 순수 로직 (모델 · 파서 · source). Flutter 의존이 없어 unit test 를 붙이기 쉽습니다.
- `state/` : `ChangeNotifier` 서브클래스. 화면과 순수 로직 사이의 얇은 층입니다.
- `ui/` : 위젯 트리. 재사용 위젯은 `widgets/` 하위에 모아 두었습니다.

**주요 패키지**
- `http` — Naver endpoint 호출용입니다. Dart 표준 `HttpClient` 대비 platform-agnostic 하고, 응답 bytes 접근이 편해서 골랐습니다 (EUC-KR 디코딩 때문에 필요했습니다).
- `provider` — 상태관리.
- `meta` — `@immutable` 애너테이션용입니다 (transitive 지만 명시했습니다).

**차트는 직접 CustomPainter 로 그렸습니다.** 캔들 + 토큰 색 (`chartLineUp` / `chartLineDown`) + Figma 여백을 동시에 맞추기 좋은 패키지가 사실상 없어서 직접 그리는 편을 택했습니다. 축 라벨 · 거래량 바 · 툴팁 같은 세부 렌더링은 시간상 생략했습니다 (선택 항목).

**디자인 토큰은 스타터의 것을 그대로 사용했습니다.** `AppColors` / `AppDimens` 값을 변경 없이 썼고, 새 토큰은 추가하지 않았습니다. 필요한 값이 이미 다 있었습니다.

## 일별 시세 페이지 이어받기

일별 시세는 HTML 응답 1페이지가 10 거래일이라서, 기간 탭이 요구하는 만큼만 그때그때 이어받는 방식으로 구현했습니다. 로직은 `DetailStore._loadForPeriod` 에 있습니다.

- 첫 진입 시 `1개월(2페이지)` 을 로드합니다. page 1 응답의 `맨뒤` 링크에서 마지막 페이지 번호를 뽑아 `_knownLastPage` 로 캐시합니다.
- `3개월` 로 넘어가면 page 3~6 만 새로 요청하고, 1~2 는 재사용합니다.
- `6개월` 은 7~12 만 추가, `1년` 은 13~25 만 추가로 받습니다.
- `_knownLastPage` 를 초과하는 페이지는 요청하지 않습니다.

mock 은 삼성전자(005930) 3페이지 · SK하이닉스(000660) 1페이지만 담고 있어서, 다른 심볼이나 3페이지를 넘는 요청은 그 시점부터 빈 페이지로 처리해 상세 화면이 죽지 않도록 해두었습니다.

## Figma 에 없어서 직접 정한 부분

- **로딩** — 관심 새로고침은 헤더 아이콘 자리에 원형 진행 표시로 두었습니다. 검색은 결과가 비었을 때만 중앙 스피너, 결과가 이미 있으면 그대로 두고 백그라운드로 갱신합니다.
- **네트워크 에러** — 스토어에서 조용히 삼키고 이전 값을 유지합니다. 강한 에러 UI 를 띄우면 화면이 자주 흔들려 부자연스러워서, 시세를 못 받은 상태는 스켈레톤으로 두는 편이 자연스럽다고 봤습니다. 실서비스라면 재시도 / 오프라인 배너를 넣었을 지점입니다.
- **긴 종목명** — 이름 필드만 `maxLines: 1` + ellipsis 로 처리했습니다. 우측 가격 컬럼이 잘리지 않도록 이름 쪽만 자르게 두었습니다.
- **토스트 노출** — 1.8초로 잡았습니다. 문구를 읽을 수 있으면서 다음 조작을 오래 안 막는 시간대라고 봤고, 등장 / 퇴장은 220ms `fade + slide(0→4px)` 로 두었습니다.
- **시세 없는 행 정렬** — 현재가 / 등락률 정렬 시 아래로 밀었습니다. 위에 두면 같은 "빈 값" 이 여러 개 몰려 순서가 흔들려 보이는 게 어색해서요. 가나다순은 메타(이름) 만 있으면 되기 때문에 그대로 뒀습니다.
- **긴 검색어** — 결과 없음 문구에 그대로 노출되면 안내가 두 줄을 넘어가 레이아웃이 깨질 수 있어, 24자에서 자르고 `…` 를 붙였습니다.
- **차트** — 시안의 세밀 렌더링(캔들 두께 · 축 눈금) 까지는 옮기지 못했습니다. 상승 / 하락 색과 위아래 요소 배치만 맞췄습니다.

## 막혔던 지점

- **일별 HTML 인코딩** — 응답이 UTF-8 이 아니라 EUC-KR 이라, 처음 mock 을 저장할 때 한글이 다 깨졌습니다. 원격 응답을 PowerShell 로 CP949 디코딩 후 UTF-8 로 재저장해 `assets/mock/` 에 넣어두고, 앱에서는 `rootBundle` 로 그냥 읽을 수 있게 정리했습니다. 실 endpoint 를 직접 호출하는 경로에서는 `bodyBytes` 를 EUC-KR 로 디코딩하도록 했습니다.
- **일별 표의 "전일비"** — 표에 별도 컬럼이 있긴 한데 부호(±) 와 절대값이 두 노드로 나눠져 있어 파싱이 번거로웠습니다. 파서를 단순화하기 위해 종가 / 시가 / 고가 / 저가 / 거래량 5개만 뽑고, 표에서는 이전 행 종가로 diff 를 다시 계산해 색을 붙였습니다.
